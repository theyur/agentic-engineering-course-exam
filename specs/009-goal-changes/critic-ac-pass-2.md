## Notes

### MINOR-1: The catalog-habit half of the "used by goals" edge case is left out for a reason that does not hold, and AC-105 departs from the file's refusal convention
- **Where**: acceptance.md, the edge-case line "A habit unpublished, or a custom habit used only by ended goals, is still 'used by goals'" (lines 268-272); AC-105 (lines 1497-1503); the convention "A refusal is written by its text." (line 111).
- **Against**: spec.md Edge Cases ("A habit unpublished, or a custom habit used only by ended goals: still 'used by goals' (slice 4 FR-033, FR-035)"); FR-020; SPEC §4 ("Administrators can create, edit, publish, and unpublish catalog entries"); the AC rule that every value is a concrete literal.
- **Continues**: MINOR-7
- **Reasoning**: The catalog case is skipped because "in a seeded catalog the demo accounts' goals may already use the habit". That problem comes from using a seed habit, not from the API. An item can have its administrator create and publish its own catalog habit, which no other goal in the database uses. Then the user puts a goal on it and ends it, and unpublishing without confirmation must leave the habit Published (FR-033's effect). That effect can be checked without the slice 4 text, the same way AC-105 checks the custom habit's effect. So the risk pass 1 named is still not checked for catalog habits. FR-020 tells the implementation to filter ended goals out of the catalog's goal counts, and code that reuses that filter for FR-033's "used by goals" check would unpublish a habit an ended goal still uses with no confirmation, and no item would catch it. AC-064 unpublishes "with confirmation", so it cannot detect this. The reasoning for AC-105 is also uneven. The refusal text is left out because slice 4 FR-035 is not restated in spec.md, yet the item relies on another slice 4 FR-035 output that is also not restated ("reading the custom habit ... gives 1 goal that uses it"). Its Then step "the deletion is refused and changes nothing" names no outcome, which departs from the file's own convention (line 111) and from the concrete-literal rule. The step is still discriminating enough here, because the next step checks that the habit and its use remain.

### MINOR-2: The FR-031 Coverage note says only the amount 0 goes unchecked, but the amount 1 is unchecked too
- **Where**: acceptance.md, Coverage row FR-031 (line 184): "That the results name no amount is checked for the amounts 5, 10, 15, 20 and 25 (AC-089); the amount 0 is not checked ..."; AC-089's "no result contains" list (line 1312).
- **Against**: spec.md FR-031 ("Reduce, count at most 1 'sweet'", and results "never ... a goal, habit, note, outcome, unit or amount"); US6-AS1.
- **Continues**: MINOR-8
- **Reasoning**: The demo amounts are 15, 20 and 25 (Reading), 10 and 5 (Meditation), and 1 for Sugar's target and 0 for its records. AC-089 leaves out both 0 and 1, but the note names only 0. The note's reason for leaving out 0 ("a result may contain that digit for another reason") would apply to 1 just as well. Also, AC-089's first Then step fixes all three results exactly, and none of those texts contains 0 or 1. So the note is not accurate about what is unchecked, and the stated reason is not supported by the expected results.
